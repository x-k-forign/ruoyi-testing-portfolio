# T4.6 正常业务链 104条断言说明

## 变量与判定口径

- HTTP状态是pm.response.code；业务code是响应JSON里的code，两者独立判断。例如退出后HTTP200、业务401符合当前场景预期。
- t46Name、t46UserId、token来自本轮输入或响应。证据中的新用户为165，已清理；下一轮必须取得新的ID，不能固定写165。
- 部门202、角色101是本项目已核实的测试前置，并在正常链中再次检查。新用户权限应仅包含list/query。
- 管理员当批部门202基准为25个ID；用实际当批集合比较，不把25作为未来运行的固定预期。

## 怎样理解这些检查的边界

1. 创建请求自身只有HTTP、业务code及字段类型3项检查；真正的保存结果由后续“查询提取ID”和“详情回查”共同核验。
2. 删除和退出的成功响应也各只有3项通用检查；随后分别用列表回查和旧token访问验证效果。
3. “字符串且非空”不等于凭证签名已经验证；“!user”为真也不完全等同于JSON中不存在user字段。本清单按现有脚本实际条件描述，没有把检查能力写得更强。
4. 所有断言通过只说明本次正常业务链符合这些检查。T4.5发现的密码5/21位新增接口缺陷仍保留，不能用这104条通过关闭它。
