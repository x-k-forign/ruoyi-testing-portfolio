# T4.5 执行说明与结果

## 本阶段测试的业务链

1. 建立管理员、部门A查询用户、部门A有限新增用户、部门B查询用户的有效会话，核实权限与部门。
2. 正常新增对照 → 单项参数/权限异常请求 → 管理员写后读取 → 清理本例新增 → 恢复核验。
3. 普通用户详情查询 → 跨部门同条件查询对照 → 全部分页ID与管理员当批基准比较。
4. 无认证/无效凭证访问 → 退出专用会话 → 旧凭证被拒 → 独立有效会话对照。
5. 错误密码或错误验证码登录 → 不获得新token → 无凭证访问仍被拒绝。

执行日期：2026-10-14。负责人：x-k-forign（项目测试负责人）。Postman MCP管理集合，Postman CLI 1.73.0连接本机真实后端执行；验证码由AI识别。未使用Computer Use，未关闭验证码，不属于Mock测试或Python自动化框架课程。

## 结果与统计

本轮25条唯一用例：23通过、2失败。18个写请求变体映射15条用例，认证/范围及登录补证另10条。Postman保存23个请求定义，参数组通过18行数据分别运行，分页组会重复请求同一定义。

有效CLI运行100次请求、326条断言，其中322通过、4失败。失败断言分属密码5位、21位两条用例，各自“应拒绝”和“无新增”两项失败。请求数、断言数和唯一用例数不混算。准备账号、获取验证码及最终补偿清理不计入100次CLI请求。

首次错误验证码运行得到“验证码已失效”，属于前置准备异常，保留原日志，不计有效错误验证码用例或产品缺陷；重新获取验证码并使用独立环境后，只将code改错，复跑通过。该无效尝试的1次请求不计入上述100次。类型错误响应的日志解析曾修正转义处理，直接重解析原日志，未虚构额外执行。

有效写场景仅pwd5、pwd21退出码1，其余16个写场景退出码0；范围认证、错误密码及错误验证码有效复跑退出码均0。CLI未登录云端的提示是运行报告上传限制，实际本地执行和退出码保留在日志中。
