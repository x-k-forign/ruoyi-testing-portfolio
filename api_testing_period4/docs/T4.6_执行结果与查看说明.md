## 重新导入发现的问题与处理

第一次通过MCP createCollection导入标准JSON时，请求结构被保留，但事件脚本和Bearer token变量参数丢失。首次CLI实际发18个请求，却没有运行任何脚本/断言；退出0不构成通过。数据库前后用户未变化。管理员登录曾产生会话，随后按本批唯一时间窗口匹配，通过正常在线会话管理接口注销；补偿管理员也退出并回查401。

使用请求级MCP导入操作从同一脱敏文件补齐events和auth，重新读取并逐项比较名称、方法、URL、Body、认证变量和脚本内容，20条均与交付文件一致后才复跑。因此本次证明的是**MCP分步导入并核对后的CLI复现**，没有声称桌面UI一次导入成功。桌面导入也应先检查脚本和认证是否完整。首次缺失版本、原始日志及补偿证据保留。

导入空环境和本地运行环境均新建；不加载旧globals、旧token或旧用户ID。本地输入管理员密码、本轮合规新密码、唯一账号、两张新验证码的uuid/code。动态token、ID及分页基准在pm.variables运行期产生，最后清空。JSON模板只含空凭据或变量引用；“secret”类型本身不代表脱敏，实际值也已核查。
