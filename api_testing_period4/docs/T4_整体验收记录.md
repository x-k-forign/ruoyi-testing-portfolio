## 迁移题的AI辅助回答

### 1 写请求的HTTP、业务状态与后续查询分别证明什么

以POST /system/user为例：HTTP状态说明传输层返回情况；正文code/msg说明服务端报告的业务分支；管理员按本批唯一账号查列表、提取ID并读详情，才证明对象确实保存以及部门、角色、状态是否正确。若业务报告失败却新增了记录，应保留请求条件、响应、前后快照、目标ID和时间，按规则登记失败或关联已有缺陷，追查保存流程、事务边界及日志。先记录再清理本批异常数据，不放宽断言，也不用无权限账号的空列表证明没有写入。

### 2 重导入后登录失败但查询成功，怎样排除误用管理员身份

核对请求、文件夹、集合的认证继承和手工Authorization头；检查局部、迭代数据、环境、集合、全局变量是否覆盖了目标token。登录前清对应旧凭据，失败不保存新值，阻止依赖步骤；检查查询是不是旧对象，别把历史数据当本次创建结果。用同一实际请求凭证访问/getInfo核对userId、userName及权限，并以No Auth返回401作对照。管理员和普通用户分开变量，不能只根据变量名或查到的用户名判断操作者身份，也不要将真实token输出到共享日志。

### 3 有限账号新增失败，怎样确认是权限或关联范围问题

先确认当前凭证有效、账号身份正确、确有该场景要求的权限；核对JSON格式、字段类型、必填项、唯一用户名及验证码前置。用管理员及有权有限身份的合法请求作对照，每次只改身份或目标部门/角色；“不存在”与“存在但无权选择”分别准备。记录实际403/500与原因，同时用有权账号做写后回查。T4.5中无add权限的154、具有add的155、范围外部门204/角色103及不存在ID分别有前置和结果，因此不能只用一次失败响应概括全部授权验证。
