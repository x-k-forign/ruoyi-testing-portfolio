# T4阶段桌面端兼容说明

适用本机Postman 9.12.2，内置Postman Runtime 7.29.0、Sandbox 4.0.6。2026-10-14对T4阶段74个请求的脚本进行兼容适配，目录和请求名称保持不变。本说明不改写T4.3～T4.6的历史执行记录，也不代替T4.6用户验收。

## 修改了什么

- 移除pm.execution依赖，集合顺序控制使用当前桌面版支持的postman.setNextRequest。
- 动态凭证、用户ID和步骤进度写入当前环境，支持按顺序单独发送；完成退出及清理后清除本批动态值。
- T4.4/T4.6管理员登录只检查管理员登录输入；新用户名、新密码、新用户验证码分别在实际需要的步骤检查。T4.6同时保存adminToken别名，继续保留t46AdminToken及链路进度。
- 前置失败时，将当前运行请求改为非网络协议t4blocked，再停止后续步骤，保证旧版不会因仅抛异常而继续发送POST/DELETE。看到t4blocked/Invalid protocol说明保护阻止了请求，应查看控制台中的“请填写…”提示并补齐前置；不要删掉保护。
- T4.5如果拒绝请求没有新增用户，“04 清理”会改为GET /getInfo只读检查管理员身份，之后继续恢复核验，不发送DELETE。
- T4.5参数组支持Runner数据文件，也支持单独发送时从环境变量t45Case读取一行测试数据。

## 只想管理员登录

1. 选择本地环境，baseUrl当前值填写http://127.0.0.1:8080。
2. T4.6中填写t46AdminPassword的本地当前值。
3. 发送“01 验证码准备/00 获取验证码”，在“可视化”查看图片；该响应uuid同时写入t46CaptchaUuid。
4. 将同一次uuid填写到t46AdminUuid，图片答案填写到t46AdminCode。数学题填写结果，不复制题目。
5. 立即发送“02 正常业务链/01 管理员登录”。不需要提前填写新用户资料。成功后t46AdminToken和adminToken保存到当前环境。
6. 可以发送“02 核验管理员身份”。若只做登录练习而不跑完整链，使用根目录“退出管理员账号”（Bearer引用adminToken）退出，再手动清除这两个token当前值；整组清理步骤要求前面的业务步骤已经完成。

T4.4使用对应t44前缀变量。根目录原有“管理员登录/普通用户登录”保留用户现有Body配置；请填写有效username/password/code/uuid。验证码过期必须重新取得，空环境模板不会包含可直接使用的密码或token。

## 按顺序单独发送或使用Runner

正常链支持逐条Send，但不能越过前置步骤。创建前填本批唯一t44_/t46_账号名；新密码为项目确认的6～20位。新用户登录前再取新验证码，避免长时间手动操作使提前取得的验证码过期。

步骤09和12需要读取全部分页。Runner会自动重复当前请求；单独Send时重复发送当前分页请求，直到测试脚本完成集合比较、进度进入下一步骤。不要修改页码强行跳过检查。

Runner运行正常链时，需要在开始前准备两张新验证码及所有本批输入，并立即运行。仅选择对应正常链文件夹，不要不加区分地对整个T4集合一键运行。

T4.5参数组：Runner加载原T4.5_写请求数据.json。若逐条Send，把该文件中选定的一整行JSON对象放入当前环境t45Case，填好t45Prefix及场景涉及的身份token和密码变量，再从“01 管理员变更前快照”开始。缺少数据行时会明确阻止请求。只改一项场景条件，不能用其他参数错误替代预期权限拒绝。

T4.3等原手工请求仍需填写自己的用户名、ID、凭证及地址。兼容适配没有猜测或覆盖用户清空的URL、Body；例如“使用用户ID查询详情”若地址为空，应填写GET {{baseUrl}}/system/user/{{newUserId}}，并先查询提取本轮ID。
