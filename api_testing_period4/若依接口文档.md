## 一、公共约定

### 1. 地址与版本

| 项目 | 内容 |
|---|---|
| 后端直连地址，本文默认 | `http://127.0.0.1:8080` |
| 前端地址 | `http://127.0.0.1:5173`，保留 `strictPort: true` |
| 前端代理地址 | `http://127.0.0.1:5173/dev-api` |
| 后端提交 | `13db1fcef36bee9ce45d2d636a1d4e8f5ed5bbc3` |
| 前端提交 | `838965c5a18d2c61b73ec30c6e288057aaa08b63` |
| 测试库 | `ruoyi_t2_lab` |
| 本地差异 | 前端代理目标为 127.0.0.1:8080，端口为 5173，开启 strictPort |

下文 `{{baseUrl}}` 默认填后端直连地址。例如 `{{baseUrl}}/system/user/list`。若改用前端代理地址，路径仍写 `/system/user/list`，不要重复添加 `/dev-api`。

本机地址可复制到 Postman 的 URL 输入框，请求方法单独选择。带 `{userId}`、`{userIds}`、`{roleId}`、`{deptId}` 的地址仍需替换为本轮实际编号；认证和参数按各接口要求填写。

### 2. 请求头与变量

| 内容 | 填写方式 |
|---|---|
| 受保护接口认证 | `Authorization: Bearer {{adminToken}}` 或 `Bearer {{userToken}}`，按实际身份二选一 |
| JSON 正文 | `Content-Type: application/json` |
| GET 查询 | 参数放在 Params 中；通常没有请求正文，不必为了 GET 添加 Content-Type |
| 匿名接口 | 获取验证码、登录不携带历史 token，不继承集合的管理员认证 |

`isToken`、`repeatSubmit` 是前端封装的控制项，不作为 Postman 必需头照抄。不要复制浏览器全部 Cookie、Content-Length 等字段。

| 示例变量 | 来源或用途 |
|---|---|
| `baseUrl` | 上述后端直连地址 |
| `loginUsername`、`loginPassword` | 本地保管的测试凭据；不写入共享文档或导出文件 |
| `captchaUuid`、`captchaCode` | 同一次验证码响应的 uuid 和人工识别结果 |
| `adminToken`、`userToken` | 各身份本轮成功登录响应的顶层 token；不得混用 |
| `newUserName` | 本轮唯一账号名，建议 `t4_` 加时间标记，总长度控制在 2～20 位 |
| `newUserPassword` | 本轮新账号的合规密码，只保存在本地；用于创建及随后新用户登录 |
| `newUserId` | 创建后以唯一账号名查询、严格匹配后提取的实际 userId |
| `deptId`、`roleId` | 当前已核实存在、正常且允许分配的部门和角色编号 |

JSON 示例中未加引号的 `{{deptId}}` 等必须替换为有效数字；含变量的模板不是可直接交给 JSON 解析器的字面量。

### 3. 如何读响应表

- **表中HTTP状态和业务code是当前源码对应分支的预期，除明确注明外尚未在T4逐项实测。** 代理、框架错误另记实际状态，不要求所有错误都返回200。
- 业务code：`200`成功、`401`认证失败、`403`操作权限拒绝、`500`默认业务/校验异常；**不是HTTP状态码的同义词**。
- 表中空白场景行承接上一行，每行只写一个检查点；不用可能显示为文字的换行标签。
- 正常消息通常为“操作成功”或“查询成功”；异常消息按失败原因核对，不强行统一文案。
- 写操作还要回查数据。源码返回某个code，不等于产品已满足业务预期；未知结果标“待实测/待核对”。

## 二、认证接口

### 1. 获取验证码

**GET `{{baseUrl}}/captchaImage`**

本机地址：GET `http://127.0.0.1:8080/captchaImage`

#### Request

- 认证：无需登录。
- Query：无必需参数。
- Body：无。

#### Responses

| 场景 | HTTP状态 | 业务code | 预期结果／检查点 |
|---|---|---|---|
| 验证码开启 | 200 | 200 | captchaEnabled=true；uuid为非空字符串。 |
|  |  |  | img为非空Base64图片；msg="操作成功"。 |
| 验证码关闭 | 200 | 200 | captchaEnabled=false；不要求返回uuid、img。 |
| 图片生成IOException被捕获 | 200 | 500 | msg为错误说明；不能继续登录。 |

注意：项目保持验证码开启，使用同一次uuid与图片，人工识别；不改开关、不读取缓存答案。

关联用例：登录前置，不单独新增用例。

### 2. 登录

**POST `{{baseUrl}}/login`**

本机地址：POST `http://127.0.0.1:8080/login`

#### Request

认证：无需旧 token。Body 类型：`application/json`。

| 字段 | 类型 | 要求 |
|---|---|---|
| username | string | 必填，登录账号；当前登录实现限制 2～20 位 |
| password | string | 必填；本项目确认的测试规则为 6～20 位 |
| code | string | 验证码开启时填写本次人工识别结果，数学题填写计算结果 |
| uuid | string | 验证码开启时填写与 code 同一次取图得到的标识 |

```json
{
  "username": "{{loginUsername}}",
  "password": "{{loginPassword}}",
  "code": "{{captchaCode}}",
  "uuid": "{{captchaUuid}}"
}
```

#### Responses

| 场景 | HTTP状态 | 业务code | 预期结果／检查点 |
|---|---|---|---|
| 账号、密码、验证码有效 | 200 | 200 | msg="操作成功"；顶层token为非空字符串。 |
| 密码错误／账号不可用 | 200 | 500 | msg说明登录失败；不返回新的token。 |
| 验证码错误／过期／已消耗 | 200 | 500 | msg说明验证码错误或失效；不返回新的token。 |

注意：先校验验证码，失败重试重新取码。密码项目规则6～20位；实现5～20位差异见BUG-T3-002。失败后清除旧token。

关联用例：TC-L01-01；其他登录异常用例在T4.2范围确认时映射。

### 3. 获取当前登录身份

本机地址：GET `http://127.0.0.1:8080/getInfo`

#### Request

#### Responses

| 场景 | HTTP状态 | 业务code | 预期结果／检查点 |
|---|---|---|---|
| 有效登录 | 200 | 200 | user.userId、userName与当前登录身份一致。 |
|  |  |  | roles为角色字符数组；permissions为权限字符数组。 |
|  |  |  | 返回pwdChrtype、isDefaultModifyPwd、isPasswordExpired。 |
| 无token／token无效或失效 | 200 | 401 | 拒绝访问，不返回受保护业务数据。 |

注意：旧会话撤权对照期间不要调用getInfo：它可能刷新权限缓存。它不能替代数据库当前关联回查。

关联用例：TC-L01-01身份补证；T4.1已用admin完成身份核验。

### 5. 退出登录

**POST `{{baseUrl}}/logout`**

本机地址：POST `http://127.0.0.1:8080/logout`

#### Request

- Header：待注销会话的 Bearer token。
- Query、Body：无。
- 用途：注销指定会话，清理本轮临时登录。

#### Responses

| 场景 | HTTP状态 | 业务code | 预期结果／检查点 |

关联用例：本批会话清理；无效/退出失效凭证场景待单独设计与编号。

## 三、用户管理接口

### 6. 查询用户列表

**GET `{{baseUrl}}/system/user/list`**

本机地址：GET `http://127.0.0.1:8080/system/user/list`

#### Request

Header：`Authorization: Bearer {{userToken}}`（管理员查询时改用 adminToken）。操作权限：`system:user:list`，同时受数据范围限制。

| Query 参数 | 类型 | 要求与含义 |
|---|---|---|
| pageNum | integer | 页码，默认 1，练习时显式填写 |
| pageSize | integer | 每页数量，默认 10 |
| userId | integer | 可选，用户编号精确筛选 |
| userName | string | 可选，账号名模糊匹配 |
| phonenumber | string | 可选，手机号模糊匹配 |
| status | string | 可选，`0` 正常、`1` 停用 |
| deptId | integer | 可选，部门及其子部门条件；仍受操作者数据范围约束 |
| params[beginTime] | string | 可选，创建日期起点，如 `2026-10-13` |
| params[endTime] | string | 可选，创建日期终点 |

Body：无。示例：

```http
GET {{baseUrl}}/system/user/list?pageNum=1&pageSize=10&userName={{newUserName}}
Authorization: Bearer {{adminToken}}
```

#### Responses

| 场景 | HTTP状态 | 业务code | 预期结果／检查点 |
|---|---|---|---|
| 有权限且存在匹配用户 | 200 | 200 | msg="查询成功"；rows为本页用户数组，total为总条数。 |
|  |  |  | 核对rows内userId、userName、deptId及status。 |
| 无匹配或被数据范围过滤 | 200 | 200 | rows=[]；total=0；不能仅凭受限查询断定对象不存在。 |
| 无token／token无效或失效 | 200 | 401 | 拒绝访问，不返回受保护业务数据。 |
| 缺少本接口操作权限 | 200 | 403 | msg="没有权限，请联系管理员授权"；不返回受保护数据。 |

注意：查全数据范围需遍历全部分页。按账号提取ID前必须精确匹配且仅一条；角色关联另查详情。

关联用例：TC-A05-01；T4.1已完成管理员查询复现（不等于TC-A05-01）。

### 7. 获取用户详情或新增初始化选项

**GET `{{baseUrl}}/system/user/{userId}`**

本机地址：GET `http://127.0.0.1:8080/system/user/{userId}`

新增初始化选项使用 **GET `{{baseUrl}}/system/user/`**，注意末尾斜线。

本机初始化地址：GET `http://127.0.0.1:8080/system/user/`

#### Request

- Header：当前身份 Bearer token。
- 操作权限：`system:user:query`。
- Path：查询详情时 userId 为必需的整数；初始化选项不带编号。
- Body：无。查询详情时服务端检查目标用户数据范围。

#### Responses

| 场景 | HTTP状态 | 业务code | 预期结果／检查点 |
|---|---|---|---|
| 存在且允许访问的用户 | 200 | 200 | data为目标用户；userId、userName、deptId应正确。 |
|  |  |  | roleIds、postIds为已有关联；roles、posts为可用选项。 |
| 新增初始化，不带userId | 200 | 200 | 返回roles、posts；不要求返回目标data、roleIds、postIds。 |
| 普通身份被用户范围校验拒绝 | 200 | 500 | msg说明无权访问用户数据；不应返回目标详情。 |
| 目标不存在 | 待核对 | 待核对 | 不应返回其他用户信息；不预设为HTTP404。 |
| 无token／token无效或失效 | 200 | 401 | 拒绝访问，不返回受保护业务数据。 |
| 缺少本接口操作权限 | 200 | 403 | msg="没有权限，请联系管理员授权"；不返回受保护数据。 |

注意：roles选项不等于全部可分配。响应不应包含password。

关联用例：TC-A04-01；TC-C01-01写后回查。

### 9. 新增用户

**POST `{{baseUrl}}/system/user`**

本机地址：POST `http://127.0.0.1:8080/system/user`

#### Request

Header：Bearer token、`Content-Type: application/json`。权限：`system:user:add`，还要检查可分配部门和角色范围。

| Body 字段 | 类型 | 正常链填写要求与实现差异 |
|---|---|---|
| userName | string | 必填且未占用；页面 2～20 位，后端实体非空且最多 30 位；正常链使用 2～20 位 |
| nickName | string | 正常链必填；页面必填，后端实体最多 30 位，没有同等非空注解 |
| password | string | 正常创建必须提供；采用项目确认的 6～20 位并满足当前字符类型配置；后端实体没有同等长度注解 |
| deptId | integer | 正常链提供有效、允许分配的部门编号；空部门行为保留观察 |
| roleIds | integer[] | 正常链提供有效、允许分配的角色编号数组；空角色行为保留观察 |
| postIds | integer[] | 可选岗位编号数组，无岗位时用 `[]` |
| status | string | 正常链填 `"0"`；`"1"` 表示停用 |
| sex | string | 可选，`"0"` 男、`"1"` 女、`"2"` 未知 |
| phonenumber | string | 可选；页面有手机号格式规则，后端实体只限制最多 11 位；非空时检查唯一性 |
| email | string | 可选；后端格式校验、最多 50 位，非空时检查唯一性 |
| remark | string | 可选备注，本链可省略 |

账号和昵称另有 XSS 校验。上述“正常链填写要求”不是声称所有字段在所有入口均有相同的服务端必填校验。缺失、null、空字符串和空数组需分别设计，不能混为一种请求。

```json
{
  "userName": "{{newUserName}}",
  "nickName": "T4接口测试",
  "password": "{{newUserPassword}}",
  "deptId": {{deptId}},
  "roleIds": [{{roleId}}],
  "postIds": [],
  "status": "0",
  "sex": "2"
}
```

#### Responses

| 场景 | HTTP状态 | 业务code | 预期结果／检查点 |
|---|---|---|---|
| 合法资料及关联 | 200 | 200 | msg="操作成功"；不保证返回userId。 |
|  |  |  | 按唯一账号查询ID，再回查部门、角色、状态正确。 |
| 账号／非空手机号／邮箱重复 | 200 | 500 | msg说明重复项；有权身份回查无新用户。 |
| 实体必填、长度或格式校验失败 | 200 | 500 | msg说明校验错误；有权身份回查无新增。 |
| 普通身份被部门／角色范围校验拒绝 | 200 | 500 | msg说明无权访问相应数据；无新用户及非法关联。 |
| 仅密码5位 | 待实测 | 预期拒绝；具体码未约定 | 按项目6～20位要求应拒绝；T3已发现实际200并创建成功，关联BUG-T3-002。 |
| 无token／token无效或失效 | 200 | 401 | 拒绝访问，不返回受保护业务数据。 |
| 缺少本接口操作权限 | 200 | 403 | msg="没有权限，请联系管理员授权"；写请求不得改变数据。 |

注意：正常链同时提交deptId和roleIds，无独立“分配部门”请求。无效用例每次只改一个条件。

关联用例：TC-C01-01；TC-C05-01、TC-C06-01/02、TC-C07-03/04。

### 10. 修改用户及部门、角色关联

**PUT `{{baseUrl}}/system/user`**

本机地址：PUT `http://127.0.0.1:8080/system/user`

#### Request

Header：Bearer token、`Content-Type: application/json`。权限：`system:user:edit`。

Body 以接口 9 的用户字段为基础，增加必需的 `userId`（integer）。先读取目标当前详情，保留非目标字段，仅改变本例目标项；不要把 PUT 当作任意局部 PATCH，也不要借此重置密码。

```json
{
  "userId": {{newUserId}},
  "userName": "{{newUserName}}",
  "nickName": "T4接口测试",
  "deptId": {{deptId}},
  "roleIds": [{{roleId}}],
  "postIds": [],
  "status": "0",
  "sex": "2"
}
```

该模板只适用于本轮按对应模板创建的对象；修改已有对象时需保留它真实的昵称、岗位、状态等配置。

#### Responses

| 场景 | HTTP状态 | 业务code | 预期结果／检查点 |
|---|---|---|---|
| 合法修改 | 200 | 200 | msg="操作成功"；回查目标字段及关联正确，其他配置保留。 |
| 实体校验失败／唯一性冲突 | 200 | 500 | msg说明原因；原配置不应被本次失败请求改变。 |
| 用户保护／数据范围校验拒绝 | 200 | 500 | 拒绝修改；回查用户及关联保持原状。 |
| 无token／token无效或失效 | 200 | 401 | 拒绝访问，不返回受保护业务数据。 |
| 缺少本接口操作权限 | 200 | 403 | msg="没有权限，请联系管理员授权"；写请求不得改变数据。 |

注意：先保存基线，保留非目标字段；结束恢复。BUG-T3-003/004仍未修复。

关联用例：TC-M07-02（隔离事务场景）；其他变更用例按执行范围映射。

### 11. 获取用户角色授权信息

**GET `{{baseUrl}}/system/user/authRole/{userId}`**

## 六、项目规则与后续测试对应

### 1. 正常业务链顺序

1. 获取验证码 → 管理员登录 → 获取当前身份，确认操作者。
2. 核实可复用的角色、部门及实际权限 → 使用唯一账号名创建用户。
3. 按唯一账号名查询并严格匹配 → 提取本轮 userId → 查详情核对角色、部门及状态。
4. 新用户重新取验证码、独立登录 → 用 userToken 查询获准数据。
5. 按用例回查日志及持久化结果 → 用有清理权限身份清理本批用户 → 注销本批会话并清除动态变量。

任一步失败就停止依赖它的后续操作，不能借旧账号或管理员身份拼接“成功链”。这是执行说明，不是已经执行的记录。
