# 业务测试

## 定义

```
为了帮用户办成一件事，软件提供的一整套相关功能。
搜索商品 → 加入购物车 → 提交订单 → 支付。
```

检查多个功能连起来使用时，能不能顺利办成一件事，前后传递的数据和处理结果对不对。

## 流程

需求文档阶段

```
1.需求分析：弄清楚应该做什么，明确测试范围。
2.测试用例：写清每一项具体怎样操作、怎样判断结果。（重点查看主流程图）
3.预期依据核对：确认“应该得到什么结果”有依据，把不明确的规则列出来，再修正测试点和用例。
4.风险评估：想清楚哪里可能出问题、出了问题影响多大，决定先测什么，以及怎样减少风险。
5.测试计划：安排准备怎样测
```

软件阶段

```
1.执行测试用例
2.缺陷跟踪管理：问题反馈，跟踪
3.编写测试报告
```

# AI辅助测试

## 需求分析

```
1.分析需求
2.评审需求合理性，提出需求不足之处
```

提示词

```
1.第一点子主题为需求：分析好对应需求，不需要复杂化
2.第二点子主题为分析：使用等价类划分法，进行相关的分析
3.第三点子主题为提取测试数据：下面是原则1.有效数据测试：多个有效数据组合测试：指的是同一场景中，各输入项都使用有效数据，例如“有效账号＋对应正确密码”，不是把多个账号同时输入。2.无效数据测试：单个无效数据项+其他全部有效数据项
4.第四点子主题为： 评审合理性：评审需求合理性，提出需求不足之处
```

## 测试计划

```
根据关键数据(需求文档)，编写测试计划
```

### 需要AI完成的任务

```
1.明确测试范围
2.设置进度安排（例如几天，几周，几个月）
3.人力物力的分配
4.制定整体测试策略
5.风险评估与规避措施
```

### 提示词

```
角色：你是一名软件测试工程师。
任务：根据提供的项目资料，编写测试计划与方案。

输入：
1. 项目需求及相关资料：（粘贴内容或提供文件）
2. 测试目标：（本次希望验证什么）
3. 测试周期：（填写期限；学习项目可不设固定周期）
4. 测试人员：（人数、角色；使用AI时说明分工）
5. 已有环境与限制：（没有明确的信息标为待确认）

要求：
1. 明确测试范围：本轮测什么、暂不测什么，以及理由。
2. 制定测试策略：采用哪些测试方式，分别检查什么、为什么。
3. 评估风险：说明可能的问题、影响、优先级及应对措施。
4. 安排执行顺序：根据风险和前置依赖安排；未提供周期时不编造日期。
5. 列出环境、账号及测试数据需求，区分已具备和待准备。
6. 明确准入与退出条件：什么时候可以开始、什么时候可以结束；说明失败、阻塞和剩余风险如何处理。
7. 说明用例执行结果、证据、缺陷、复测和回归的记录方式。
8. 已有需求、风险和用例应相互对应，发现矛盾或遗漏时指出并给出补充建议。
9. 不明确的规则单独列为待确认，不编造需求、环境状态或实际测试结果。

输出：
内容简洁、具体、可执行，适当使用表格。
输出格式及保存位置：（自行填写）
```
