## 五种方法的代表与理由

| 方法 | 代表用例 | 为什么使用 |
|---|---|---|
| 等价类 | TC-L02-01/02、L03-02、L04-01/02；RK02 | 把不存在、空账号、错误密码、停用、删除分开，避免一种拒绝遮挡另一条规则 |
| 边界值 | TC-L09-01—08、C09-01—06；RK12/RK07 | 区分登录账号2—20、登录密码5—20、创建密码6—20；对照端点、相邻及内点，不能套用练习的8—16 |
| 判定表 | TC-C01-01、C05-01、C06-01/02；RK04 | 有操作权限不代表能分配任意关联；两类条件组合比单列输入值更能说明授权边界 |
| 状态迁移 | TC-M05-01/M06-01；RK06 | 同一账号从正常变禁用，分别检查新登录与旧会话；旧会话不能被重新登录破坏 |
| 场景法 | TC-E01-01/E02-01/E03-01；RK01 | 用同一userId串起创建、登录、访问、变更及日志；起点失败则停止依赖成功的后续步骤 |

边界用例中的每个参数值独立执行并留结果，不因一条TC有多个取值而将其中一次成功推广到全部。长度单位使用ASCII字符；输入框限制与服务端校验分别取证。

| 新增权限 | 目标关联在范围内 | 预期 | 对应设计 |
|---|---|---|---|
| 有 | 是 | 允许新增，回查关联正确 | C01正常创建及A02乙的正向对照；不得用admin证明普通范围校验 |
| 有 | 否 | 范围校验拒绝，不新增 | C06-01/02 |
| 无 | 是 | 权限拒绝，不新增 | C05-01 |
| 无 | 否 | 仍应拒绝，不据此单独判断范围检查有效 | 需求导图中的组合对照；C05扩展取值，执行时单独留证，不替代C06单项验证 |

以上组合均可作为设计条件，不预设权限检查和范围检查的实际先后顺序。双条件均无效用于组合覆盖；单项规则验证仍保持其他条件有效。

### 细节修订清单

- L06前置中的“有效新码”应理解为取码时有效，再等待该原码过期；最终提交的目标码必须已过期，不能混用新码。
- M07-02步骤应表述为“预置故障条件→提交变更，在事务执行时触发异常→回查与恢复”，不在提交前单独抛异常冒充事务失败。
- C09-06输入21位若被截断为20位，需要记录实际提交长度。有效20位被接受不能反判为“21位后端校验失败”。

## AI辅助场景说明

密码和验证码同时错误，不能证明两种校验都有效：验证码可能先拒绝，请求没有进入密码匹配。验证密码错误时必须使用新有效验证码、正常未锁定账号及合规来源，并确认拒绝原因指向密码。

当结果取决于多个条件共同成立，例如“有新增权限”与“关联在可分配范围”，判定表适合检查条件组合。每种组合各自留证；不能把某个拒绝结果当作所有条件分别正确的证明。
