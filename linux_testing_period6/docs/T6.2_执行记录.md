## 管道与重定向

实际通过Bash的noclobber保护（set -o noclobber）向不存在的新文件写入，避免覆盖已存在目标：

```bash
grep -nF -- 'T3_FAULT' "$log_file" > "$out_dir/event_index.txt"
date -Is >> "$out_dir/event_index.txt"
```

这里展示关键结构；本批原样命令还在追加时间前写入# extracted_at=标签，完整参数和执行状态保存在命令台账。`>`写入新文件，`>>`追加；它们没有指向源日志。完整事件同样以新文件为目标，原日志摘要和mtime未改变。

另对“没有匹配”这个已知场景演示了管道状态：

| 场景 | grep / head状态 | 整条管道状态 |
| --- | --- | --- |
| 默认Bash管道 | 1 / 0 | 0 |
| 开启pipefail | 1 / 0 | 1 |

默认情况下，管道通常采用最后一条命令的退出状态；head本身正常结束，不代表上游grep找到了事件。pipefail可以暴露上游非零状态，但仍要区分grep的1是无匹配、2是错误。即使管道状态正常，head截断输出仍可能让证据不完整。

需要理解：

- 文件路径决定查谁，工作目录决定相对路径含义；同名文件不保证是同一份证据。
- grep没有输出时，先看退出码和stderr，再结合路径与权限判断，不能直接说没有异常。
- 固定文本匹配、上下文、完整事件是三个层次；显示行数不等于事件数量。
