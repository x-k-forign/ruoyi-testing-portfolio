## 需要理解的关键点

- **分层判断：** 进程存在、端口监听、TCP连接成功、HTTP响应和内容正确分别提供不同证据。
- **失败发生在哪里：** 本次错误端口在TCP阶段拒绝，未进入HTTP；服务日志没有这次失败请求是与该路径一致的结果，不能套用若依审计缺陷结论。
- **一个因素的对照：** 仅改变客户端端口，并在相同服务进程下修正，才能把本次恢复与该因素建立联系。
- **恢复后重做原操作：** 相同请求成功，再做相关最小回归；不能只看进程或首页可见就宣布全部正常。
- **localhost与范围：** 请求在Linux执行，127.0.0.1指Linux本机；本例没有完成Windows跨机连通性测试。
- **收尾区别：** 先证明恢复访问，再停止实验服务并保留证据；最后端口关闭是计划收尾。
