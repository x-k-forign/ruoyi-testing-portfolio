# T9 UI 回归用例

用例设计放在 `tests/<业务主线>/<功能分组>/`，每份设计沿用主用例表的原 TC 编号。实际核对若依 DOM 后，对应 Python 脚本也放在同组。

| Allure 层级 | 取值 |
| --- | --- |
| epic | 若依管理系统 |
| feature | 用户创建与授权、新用户登录、菜单操作与数据访问、授权变更与账号禁用、相关日志核对 |
| story | 功能分组目录，例如创建授权、登录与退出、部门数据范围 |
| title | 用例设计的中文标题 |

Python 用例通过 `commons.allure_labels.ui_case` 登记四级标签和原 TC。普通用例使用公共夹具 `browser`，同例的多个身份分别调用 `new_browser()`。

浏览器创建和 Selenium 导包集中在 `commons/browser.py`。用例可以用 `from commons.browser import By, EC, WebDriverWait` 导入定位和显式等待工具。公共 `browser` 夹具沿用 `commons.browser` 的 10 秒隐式等待默认值。`TC-C01-01` 和 `TC-L01-01` 用 `new_browser(implicit_wait=0)` 创建独立会话，并使用显式等待观察业务状态。

| 主线 | 功能分组 | 首批回归 |
| --- | --- | --- |
| 用户创建与授权 | 创建授权 | TC-C01-01 |
| 新用户登录 | 登录与退出 | TC-L01-01 |
| 菜单操作与数据访问 | 功能操作权限 | TC-A02-01 |
| 菜单操作与数据访问 | 部门数据范围 | TC-A05-01、TC-A05-02、TC-A10-02 |
| 授权变更与账号禁用 | 待选 | 保留分组 |
| 相关日志核对 | 待选 | 保留分组 |

依据见[主线用例表](../../docs/若依主线测试用例.xlsx)、[T3 权限矩阵](../../functional_testing_period3/docs/T3.4_权限矩阵与抽检说明.md)和[T7 历史记录](../../README.md#t7执行结果)。首批均是原业务场景的 UI 回归设计。用例脚本和本地执行结果见[T9web自动化执行结果](../../README.md#t9web自动化执行结果)。

## 共通前置

- 登录经真实页面提交，验证码保持开启。两个核心用例由公共脚本从测试 Redis 取得当前页面验证码的答案后填入。
- 测试账号、角色与部门先核对本轮实际配置和归属。甲、乙、丙及部门 A、B 为身份和部门代号。每例用独立标记，不依赖前一例创建的账号。
- 写入前登记本例目标和归属，获得 ID 后补登。结束后只清理本例创建的资源，删除后回查并退出独立浏览器会话。记录清理异常，保留业务失败证据。
- 搜索、表格重载和遮罩用显式等待。核对按钮缺失前，先确认身份、目标页已就绪和有权限的正向对照。数据对照统一筛选、部门树状态和分页口径。
